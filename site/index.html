The QR label of the TigerTag ecosystemTigerQR

One sticker on a filament spool. One scan opens the right page, on any phone, with no app.

TigerQR+ is the label linked to a product of the TigerTag+ catalogue; TigerQR is the label that is not, the same logic as TigerTag and TigerTag+. This site is the public reference for what a label prints and what its qr.tigertag.io link means.

One scan, three links

Every label points to https://qr.tigertag.io/. The path alone says what it is, so an app reads it offline, without the website. Links are printed lowercase and read in any case.

A spool with a chip

TigerTag · TigerTag+ qr.tigertag.io/1d33dbda0d1080

The chip's NFC UID in hex, 14 characters. The twin chip's UID opens the same spool.

A spool without a chip

TigerData · TigerData+ qr.tigertag.io/6130922252

The TigerData id without its TigerData_ prefix: 10 or 17 digits. The long form TigerData_6130922252 opens too.

A catalogue product

TigerQR+ · public qr.tigertag.io/p/2673739332

The id_product in decimal, always 10 digits with leading zeros (p/0010303748). Labels printed with 8 hex characters (p/9f5e0644) still open.

Who gets what

LinkIts owner, signed inAnyone else
Spoolthe spoolthe spool's catalogue product and the owner's display name, never the spool
Productthe catalogue product, for everyone, with no sign-in

The owner signs in to their TigerSystem account. A spool with no catalogue product shows a private page to anyone but its owner. The weight, the note and the rack never leave.

Endings for tools: .json and .ttag

Add .json (the data) or .ttag (the file Tiger Studio imports) to any link to build your own interface: p/2673739332.json, p/2673739332.ttag.

  • On a product link: the catalogue record (?lang= picks the text language), cacheable, from any origin.
  • On a spool link: the spool for its owner (Authorization: Bearer <ID token>); anyone else is sent (303) to the product's .json / .ttag, or gets a 404 without a product.
  • A product that left the catalogue answers {"error":"not-in-catalogue"} with status 404.

Shared links carry a language, printed labels never do

A link shared from a Share button may start with the sharer's language: qr.tigertag.io/fr/p/2673739332. The page and its preview on social networks then open in that language for everyone, link-preview crawlers included. Without a prefix, the visitor's browser language decides; an unknown prefix answers 404.

The prefix is one of en fr de es it zh pt pt-pt pl ru nl. A reader handed a link drops one leading /<lang>/ first, then reads the rest, and never stores or prints it: a label made from a shared link carries the bare link, so a printed QR stays the same in every country.

Spool Label or Filament Label, TigerQR or TigerQR+

Two kinds of label, one set of formats. The pill in the corner says whether the label is linked to the catalogue.

What a label carries

  • the brand; the series in white on a black bar (the material when there is no series);
  • the colour name and its hex code(s);
  • the TigerQR or TigerQR+ pill;
  • up to four value slots on Classic, Wide and Vertical: nozzle, bed and drying temperatures, then TD or diameter;
  • the QR code, and nothing in clear next to it.

Only what does not change: never the remaining weight, the note, the rack or the owner. QR only prints the pill centred at the top over the QR, and nothing else.

How a label is drawn

The rules that make a label scan on every phone camera and print sharp on a thermal printer.

One byte segment, ECC M

The whole link, lowercase, in one byte-mode segment with error correction level M (15 %): labels get scratched and folded. A lowercase scheme cannot use the alphanumeric mode, and splitting the link into segments saves nothing.

29 × 29 modules

Every spool and product link fits a version 3 code, 29 × 29 modules. The label's white margins are its quiet zone.

Lowercase, always

Tested 2026-11-07: the iPhone camera opens a link in either case, but the Samsung camera (Galaxy S24) shows an uppercase HTTPS:// link as plain text and opens only a lowercase one.

Whole printer dots per module

Each module covers a whole number of dots: the nearest one that fills the QR box, rounded up when that stays within 6 % of the box, down otherwise. A PNG is drawn at exactly the label's size in dots, never resampled.

Tenths of a millimetre

One SVG per label, sized in millimetres, laid out in tenths of a millimetre and scaled to printer dots at 203 or 300 dpi.

Texts keep clear

Texts never run over the QR or the pill: a long text shrinks first, then is narrowed. Tiger Studio and tigersystem.io draw the same SVG, byte for byte.

Reading a link

The order a reader follows, as splitLangPrefix and parseQrPath in src/parse.ts do it.

  1. 1Drop a language prefix

    A shared link's leading /<lang>/, in any case.

  2. 2Normalise the path

    Percent-decode, drop leading and trailing /; an empty path is the root.

  3. 3Take the ending

    One .json or .ttag, any case; else a page.

  4. 4Product, older form

    p/ + 8 hex: the hex value (8 digits: the decimal reading is tried when the hex one is not in the catalogue).

  5. 5Product, printed form

    p/ + 1 to 10 digits: the decimal value; above 4294967295 is unknown.

  6. 6Spool

    10 or 17 digits, then 14 hex, then 13 hex starting with 4 (a leading 0 put back), then tigerdata_ / tigerdata- + digits.

  7. 7Anything else

    A label from a newer version: say "update the app" instead of failing.

What each shape names

PathNames
p/<8 hex>a product, older labels
p/<1 to 10 digits>a product, printed on 10 digits
p/0, p/00000000, p/ffffffff, p/4294967295"no product", never printed, 404
<14 hex>a spool with a chip, id: the UID uppercase
<13 hex starting with 4>a chip UID that lost its leading 0
<10 digits>, <17 digits>a spool without a chip, id: TigerData_<digits>
tigerdata_<digits>, tigerdata-<digits>the same, long form
anything elseunknown: "update the app" (404)

A chip UID has 14 characters and a TigerData id 10 or 17 digits, so an all-digit UID is never read as a TigerData id. A product link always starts with p/, so it never collides with a spool.

The public label API

    
Any catalogue product's label, from its id alone, drawn by tigersystem.io with the same renderer as Tiger Studio. No key, no sign-in.

    

      

        
GET https://tigersystem.io/api/public/v1/label/<id>.svg?template=<format>&dpi=<203|300>
GET https://tigersystem.io/api/public/v1/label/<id>.json
GET https://tigersystem.io/api/public/v1/label/<id>.html

        
    
          
  • .svg: the label, sized in millimetres; template is a format id (classic by default), dpi 203 or 300, unit=dots sizes it in printer dots (a PNG's source), lang picks the language of the slot words.
    • 
          
  • .json: what the label prints, its QR link, its catalogue page and the SVG URL of every format.
    • 
          
  • .html: a widget to frame on any site (theme=light|dark), documented on tigersystem.io/en/embed.

For developers

    
The reference code is published as is from qr.tigertag.io, with no dependency. Implementing these links and labels needs no licence and no payment.

    

      

        
TypeScript: read and build


import { parseQrPath, splitLangPrefix } from "./src/parse";
import { productLink, spoolLink, qrLinkFrom } from "./src/links";

const { lang, path } = splitLangPrefix("/fr/p/2673739332");
parseQrPath(path);
// { kind: "product", idProduct: 2673739332,
//   hex: "9f5e0644", format: "page" }

productLink(10303748);
// "https://qr.tigertag.io/p/0010303748"
spoolLink("TigerData_6130922252");
// "https://qr.tigertag.io/6130922252"
qrLinkFrom("chip", "1D:33:DB:DA:0D:10:80");
// { kind: "chip", link: "https://qr.tigertag.io/1d33dbda0d1080" }
